# Инструкция по настройке Visual Studio Code для JavaScript

Настройка VS Code для JavaScript сводится к трём этапам: установка самого редактора и среды выполнения, добавление базовых расширений и правка настроек для автоматизации работы. Ниже — пошаговая инструкция.

## 1. Установка необходимого ПО

**VS Code.** Скачайте с официального сайта code.visualstudio.com и установите. На Windows при установке обязательно отметьте пункт **«Add to PATH»**, иначе команда `code` в терминале не будет работать.

**Node.js.** JavaScript можно запускать и в браузере, но для разработки и запуска скриптов из терминала нужен Node.js. Скачайте LTS-версию с nodejs.org и установите. Проверьте установку командой в терминале:
```bash
node --version
```

## 2. Базовые расширения

Откройте панель расширений (`Ctrl+Shift+X`) и установите следующее. Не устанавливайте всё подряд — лишние расширения замедляют запуск редактора.

**Обязательный минимум (ESLint + Prettier)** — это «рабочая лошадка» для любого JS-проекта:

- **ESLint** (`dbaeumer.vscode-eslint`) — находит логические ошибки, потенциальные баги и нарушения стиля прямо во время набора. Подхватывает конфигурацию вашего проекта автоматически.
- **Prettier** (`esbenp.prettier-vscode`) — отвечает только за форматирование: отступы, переносы строк, кавычки, точки с запятой.

**Полезные дополнения:**

- **Error Lens** (`usernamehw.errorlens`) — показывает текст ошибки прямо на строке с проблемой, а не во всплывающей подсказке при наведении.
- **Path Intellisense** (`christian-kohler.path-intellisense`) — автодополнение путей к файлам в импортах, особенно выручает в проектах с глубокой структурой папок.
- **Auto Rename Tag** (`formulahendry.auto-rename-tag`) — при переименовании открывающего HTML/JSX-тега закрывающий меняется автоматически.
- **Live Server** (`ritwickdey.LiveServer`) — если планируете работать с HTML/CSS в браузере: запускает локальный сервер с автообновлением при сохранении. Для проектов на React/Vue не нужен — у них свои dev-серверы.

Если не хотите ставить по одному, есть **Node.js Extension Pack** — набор расширений для Node-разработки одним пакетом.

## 3. Настройка settings.json

Откройте настройки через `Ctrl+,` (или `Cmd+,` на macOS), переключитесь в режим JSON (значок `{}` в правом верхнем углу) и добавьте конфигурацию ниже. Эти настройки включают форматирование и автоисправление при каждом сохранении файла:

{
    или 

    Самый надёжный вариант — использовать панель команд, она не зависит от сочетаний клавиш и почти никогда не отказывает:
    Нажмите Ctrl+Shift+P (на Mac — Cmd+Shift+P), откроется панель команд.
    Введите Preferences: Open Settings (UI) и нажмите Enter — откроется графический интерфейс настроек.
    Если нужно сразу редактировать JSON-файл, введите Preferences: Open Settings (JSON).
}

```json
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  "eslint.validate": [
    "javascript",
    "javascriptreact",
    "typescript",
    "typescriptreact"
  ]
}
```

**Важное предупреждение:** ESLint и Prettier должны работать в связке, а не конфликтовать. Prettier отвечает за форматирование, ESLint — за поиск ошибок. Чтобы они не спорили, в конфигурации ESLint вашего проекта (`eslint.config.mjs` или `.eslintrc.js`) в список `extends` нужно добавить `prettier` последним — это отключает правила форматирования внутри ESLint и передаёт их Prettier.

## 4. Как запускать код

**Прямо в VS Code через Code Runner.** Установите расширение **Code Runner** (`formulahendry.code-runner`), откройте JS-файл, нажмите правой кнопкой в редакторе → **Run Code** (или `Ctrl+Alt+N`). Результат появится на вкладке Output.

**Через встроенный терминал.** Самый надёжный способ. Откройте терминал (`Ctrl+`` ` ``) и выполните:
```bash
node имя_файла.js
```

**Для фронтенда в браузере.** Если код использует `document`, `window` и другие browser API, запустите его через **Live Server**: откройте HTML-файл, кликните **Go Live** в статус-баре, затем откройте DevTools в браузере (`F12`) → вкладка Console.

## Итог

После этих шагов вы получаете среду, где код автоматически форматируется и проверяется при сохранении, ошибки видны сразу, а запуск скриптов занимает одну команду или клик. Для начала этого достаточно; остальные расширения добавляйте по мере необходимости, а не «на всякий случай».

# Как поменять тему в VS Code

Есть три способа — от самого быстрого до самого точного.

## Способ 1: Через панель команд (самый быстрый)

1. Нажмите `Ctrl+Shift+P` (на Mac — `Cmd+Shift+P`).
2. Введите `Color Theme` и выберите **Preferences: Color Theme**.
3. Стрелками `↑` `↓` листайте список — тема применяется сразу, вживую.
4. Нажмите Enter, чтобы зафиксировать выбор.

## Способ 2: Через настройки

1. Откройте настройки: `Ctrl+,` (или через панель команд — `Preferences: Open Settings (UI)`, если `Ctrl+,` не срабатывает).
2. В поиске введите `theme`.
3. Найдите пункт **Workbench: Color Theme** и выберите тему из выпадающего списка.

## Способ 3: Через меню

**File → Preferences → Theme → Color Theme** (в Windows/Linux). На Mac: **Code → Settings → Theme → Color Theme**.

---

## Встроенные темы

VS Code уже содержит несколько готовых тем, устанавливать ничего не нужно:

- **Dark+ (default dark)** — тёмная тема по умолчанию.
- **Light+ (default light)** — светлая тема по умолчанию.
- **Dark Modern** и **Light Modern** — более современные версии с обновлёнными цветами интерфейса.
- **Monokai**, **Solarized Dark/Light**, **Abyss**, **Kimbie Dark** — дополнительные варианты.

## Если нужна тема с Marketplace

Встроенных тем часто не хватает — тогда ставьте сторонние:

1. Откройте панель расширений (`Ctrl+Shift+X`).
2. В поиске введите `theme` или название конкретной темы.
3. Установите расширение.
4. После установки VS Code обычно сам предложит применить тему. Если нет — выберите её через панель команд (**Preferences: Color Theme**).

Популярные темы: **One Dark Pro**, **Dracula Official**, **Night Owl**, **Material Theme**, **GitHub Theme**.

---

## Важный нюанс

**Тема интерфейса и тема кода — это одно и то же в VS Code**, отдельно менять цвет подсветки синтаксиса нельзя, не поменяв тему целиком. Исключение — расширение **Material Theme Icons** и подобные, которые меняют только иконки файлов, не затрагивая цвета.

**Подсветку синтаксиса** для конкретного языка можно тонко донастроить вручную через `settings.json` → `editor.tokenColorCustomizations`, но это уже для тех, кому стандартной темы мало.

Чтобы увидеть список всех функций в текущем файле, в VS Code есть два основных встроенных способа — через панель Outline или через «быстрое открытие».

### 🎯 Способ 1: Панель Outline (боковая панель)

Outline — это отдельная панель, которая показывает древовидную структуру файла: все классы, функции, переменные и другие символы .

**Как открыть:**
- Нажмите `Ctrl+Shift+O` (Windows/Linux) или `Cmd+Shift+O` (Mac) .
- Либо через меню: **View → Open View... → Outline** .
- Либо кликните правой кнопкой по панели активности (слева) и включите Outline.

**Как пользоваться:** Кликните по функции в списке — курсор сразу перескочит к её определению . Сверху есть иконка фильтра (воронка), чтобы скрыть переменные и оставить только функции и классы .

### 🎯 Способ 2: Быстрое открытие символа (палитра)

Это самый быстрый способ, если нужно просто найти одну функцию, а не изучать всю структуру.

1. Нажмите `Ctrl+P` .
2. В появившейся строке введите символ `@` .
3. Вы увидите выпадающий список всех функций в текущем файле. Начните печатать имя — список отфильтруется.

**Бонус:** Если после `@` ввести `:`, символы будут сгруппированы по типам (функции отдельно, переменные отдельно) .

### ⚠️ Если список пуст

Outline и список символов работают на основе «языкового сервера». Если список пуст, значит, VS Code не распознал язык файла или расширение для этого языка не установлено .

**Что проверить:**
- В правом нижнем углу должно быть указано `JavaScript` (а не `Plain Text`). Если нет — кликните и выберите язык.
- Убедитесь, что установлено расширение для нужного языка (для JS обычно достаточно встроенной поддержки).

Если файл большой и функций очень много, панель Outline будет удобнее — она всегда перед глазами и позволяет прыгать между функциями без повторных вызовов палитры.
