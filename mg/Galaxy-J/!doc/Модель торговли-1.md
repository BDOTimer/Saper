Математическая модель для игры про космического торговца
- игрок летает на космическом корабле по звездным системам Галактики
- на стнациях планет существуют магазины с товарами
- цены на покупку/продажи
- задача игрока покупать дешевле - продавать дороже

Предложи математическую модель - чтобы процесс торговли был увлекательным.

---

Учитывая, что ты разрабатываешь игру с бесконечным геймплеем и уже работаешь с Three.js и производительностью, модель торговли должна быть **лёгкой для расчёта** (не тормозить цикл рендера), но **достаточно вариативной**, чтобы игрок постоянно находил новые выгодные маршруты.

Ниже — готовая математическая модель, которую можно прямо внедрять в JS-код.

---

## Базовые сущности и параметры

Определим переменные, которые будут храниться в объектах игры:

- `item.basePrice` — базовая стоимость товара (в условных кредитах).
- `system.demandLevel` — уровень спроса в системе (от 0 до 1).
- `system.supplyLevel` — уровень предложения в системе (от 0 до 1).
- `player.reputation` — репутация игрока (влияет на скидки/наценки; от 0 до 1).
- `distanceFactor` — множитель, зависящий от расстояния до системы (штраф за дальние перевозки).

---

## Формула цены покупки и продажи

Цена в каждой системе рассчитывается отдельно для каждого товара.

### Цена покупки (сколько ты платишь магазину)

```js
buyPrice = item.basePrice * (1 + system.supplyLevel - system.demandLevel) * distanceFactor
```

Логика:
- Если товара много (`supplyLevel` высокий) — цена ниже.
- Если спрос высокий (`demandLevel` высокий) — цена выше.
- Дальние системы могут иметь чуть завышенные цены из‑за логистики (`distanceFactor`).

### Цена продажи (сколько магазин платит тебе)

```js
sellPrice = item.basePrice * (1 + system.demandLevel - system.supplyLevel) * distanceFactor * player.reputationBonus
```

Где `player.reputationBonus` — бонус за репутацию, например:

```js
reputationBonus = 0.8 + 0.4 * player.reputation // от 0.8 до 1.2
```

То есть при низкой репутации тебе платят меньше, при высокой — больше.

> **Важно:** `buyPrice` всегда должен быть больше `sellPrice` в одной и той же системе, иначе получится арбитраж без риска. Это обеспечивается тем, что в формуле покупки «минус спрос» работает против игрока, а в продаже — «плюс спрос» ему помогает.

---

## Как задавать demandLevel и supplyLevel

Чтобы не хранить огромные таблицы, используй **процедурную генерацию по типу системы**. Например:

| Тип системы | demandLevel | supplyLevel | Комментарий |
| --- | --- | --- | --- |
| Промышленная | 0.7 | 0.3 | Нужны ресурсы, производят товары |
| Добывающая | 0.2 | 0.8 | Много сырья, мало готовых товаров |
| Колония/Аграрная | 0.6 | 0.4 | Стабильный спрос, умеренное производство |
| Военная/Пограничная | 0.9 | 0.1 | Высокий спрос на припасы и оружие |

Эти значения можно слегка рандомизировать:

```js
demandLevel = baseDemand + (Math.random() - 0.5) * 0.2 // ±10%
supplyLevel = baseSupply + (Math.random() - 0.5) * 0.2
```

---

## DistanceFactor: как учитывать расстояние

Поскольку у тебя уже есть координаты звёзд и камера в Three.js, расстояние между системами легко считать:

```js
const dx = s1.x - s2.x;
const dy = s1.y - s2.y;
const dz = s1.z - s2.z;
const distance = Math.sqrt(dx*dx + dy*dy + dz*dz);

// Пример: чем дальше, тем выше множитель (логистика дороже)
const distanceFactor = 1 + distance * 0.001; // +0.1% на каждую условную единицу расстояния
```

Если хочешь сделать «зоны» вместо плавного множителя, можно использовать ступенчатую функцию:

```js
if (distance < 100) distanceFactor = 1;
else if (distance < 500) distanceFactor = 1.1;
else distanceFactor = 1.3;
```

## Динамические события (чтобы торговля не была предсказуемой)

Для увлекательности добавь редкие события, которые меняют `demandLevel` и `supplyLevel` на короткое время:

1. **Авария на производстве** — `supplyLevel` падает на 30–50% на 2–4 игровых дня.
2. **Прибытие флота** — резкий всплеск спроса на топливо и припасы (`demandLevel` +40%).
3. **Торговая блокада** — в некоторых системах `buyPrice` становится очень высоким, а `sellPrice` низким (или торговля временно закрыта).
4. **Сезонный спрос** — циклические изменения (например, каждые 7 дней спрос на еду растёт в аграрных системах).

Реализуй это как модификаторы:

```js
let demandModifier = 1;
let supplyModifier = 1;

if (system.hasEvent('blockade')) {
  demandModifier = 0.7;
  supplyModifier = 1.4;
}

finalDemand = system.baseDemand * demandModifier;
finalSupply = system.baseSupply * supplyModifier;
```

Затем используй `finalDemand` и `finalSupply` в формулах цен.

## Прибыль и риск

Прибыль с одной сделки:

```js
profit = (sellPrice - buyPrice) * quantity
```

Но учти риски:

- **Пираты**: вероятность встречи зависит от расстояния и «опасности» сектора. При встрече часть груза может быть потеряна.
- **Порча товара**: скоропортящиеся товары теряют ценность со временем (например, −2% в день).
- **Изменение цен**: пока летишь, цены могут измениться из‑за событий.

Пример штрафа за время:

```js
const daysInTransit = Math.ceil(distance / player.shipSpeed);
const spoilageFactor = Math.max(0, 1 - daysInTransit * item.spoilRate); // spoilRate = 0.02 для скоропортящихся
effectiveSellPrice = sellPrice * spoilageFactor;
```

## Интеграция с твоим проектом (Three.js, бесконечный геймплей)

Учитывая твой стек и концепцию бесконечного геймплея:

- **Не храни историю цен для всех систем** — генерируй текущие цены «на лету» по формулам. Это экономит память и подходит для процедурной галактики.
- **Обновляй цены раз в N игровых минут** (например, раз в 5 минут) — это можно делать в отдельном таймере, не в кадре рендера.
- **События** можно хранить в простой структуре: массив активных событий с таймером окончания.
- **Для отладки** удобно выводить в консоль или UI «маржу» (разницу цен) между двумя системами — так игрок будет видеть потенциально выгодные маршруты.

Пример простой функции расчёта маржи для товара между двумя системами:

```js
function calculateMargin(item, systemA, systemB, player) {
  const priceA_buy = calculateBuyPrice(item, systemA);
  const priceB_sell = calculateSellPrice(item, systemB, player);
  return priceB_sell - priceA_buy; // положительная — выгодно везти из A в B
}
```

---

## Идеи для увлекательности (геймплейные следствия модели)

- **«Горячие» точки**: из‑за событий появляются временные выгодные маршруты — игрок должен быстро реагировать.
- **Специализация систем**: одни системы стабильно производят дешёвые ресурсы, другие стабильно потребляют дорогие товары — это создаёт устойчивые торговые пути.
- **Репутация как валюта**: выполняя задания фракций, игрок открывает доступ к закрытым системам или получает лучшие цены.
- **Конкуренция**: можно добавить NPC‑торговцев, которые тоже реагируют на события и могут «перехватывать» выгодные сделки.

## Пример расчёта (для понимания)

Пусть:
- `basePrice` = 100 кредитов
- Система A (добывающая): `demand=0.2`, `supply=0.8`
- Система B (военная): `demand=0.9`, `supply=0.1`
- `distanceFactor` = 1.05 (недалеко)
- `reputationBonus` = 1.0 (нейтральная репутация)

**Покупка в A:**

```
buyPrice = 100 * (1 + 0.8 - 0.2) * 1.05 = 100 * 1.6 * 1.05 = 168
```

**Продажа в B:**

```
sellPrice = 100 * (1 + 0.9 - 0.1) * 1.05 * 1.0 = 100 * 1.8 * 1.05 = 189
```

**Прибыль с единицы:** `189 − 168 = 21` кредит.

Если повезёшь 10 единиц — прибыль 210 кредитов. Если в полёте будет событие «порча» и потеряешь 20% груза — прибыль уменьшится пропорционально.

Чтобы торговля в игре была увлекательной, она не должна сводиться к простому генератору случайных чисел (RNG) или статичной таблице. Игрок должен чувствовать себя **аналитиком, спекулянтом и логистом**. 

Предлагаемая математическая модель строится на трех китах: **Базовая экономика (атрибуты планет)**, **Динамический спрос/предложение (заполненность рынка)** и **Информационная асимметрия (скрытые данные)**.

---

### Уровень 1. Базовая цена и атрибуты станций (Статика)
Каждая планета/станция имеет набор скрытых или полу-скрытых параметров, которые формируют *базовый модификатор* цены.

Пусть $P_{base}(g)$ — галактическая базовая цена товара $g$.
Каждая станция $i$ имеет атрибуты:
*   $T_i$ — Технологический уровень (от 0 до 1)
*   $W_i$ — Уровень богатства/населения (от 0 до 1)
*   $R_{i,g}$ — Ресурсная специализация (насколько станция производит товар $g$, от 0 до 1)

**Формула локального базового множителя ($M_i$):**
$$M_i(g) = 1 + (W_i \cdot D_g) - (T_i \cdot S_g) + (R_{i,g} \cdot 0.5) - (1 - R_{i,g}) \cdot 0.5$$
*(Где $D_g$ — потребность товара в богатстве, $S_g$ — потребность в технологиях).*

*Пример:* Аграрная планета ($T$ низкий, $W$ средний, $R_{еда}=1$) будет производить еду дешево, но покупать микрочипы очень дорого.

---

### Уровень 2. Динамика рынка (Спрос и Предложение)
Цены не должны стоять на месте. Они зависят от текущих запасов товара на станции $Q_{i,g}$ относительно максимальной вместимости склада $Q_{max}$.

Введем коэффициент заполненности рынка: $F = \frac{Q_{i,g}}{Q_{max}}$ (от 0 до 1).

**Цена покупки для игрока (Станция продает):**
$$P_{buy} = P_{base} \cdot M_i(g) \cdot (1 + \alpha \cdot F)$$
*Чем больше товара на складе ($F \to 1$), тем дешевле игрок может его закупить.*

**Цена продажи для игрока (Станция покупает):**
$$P_{sell} = P_{base} \cdot M_i(g) \cdot (1 + \beta \cdot (1 - F))$$
*Чем меньше товара на складе ($F \to 0$), тем дороже станция готова его выкупить.*

**Спред (Разница между покупкой и продажей):**
Коэффициенты $\alpha$ и $\beta$ задают "жадность" торговцев. Спред должен покрывать расходы на топливо, чтобы игрок не мог бесконечно возить товар между двумя соседними станциями.

---

### Уровень 3. Влияние игрока и NPC (Проскальзывание)
Если игрок скупает весь товар, цена должна резко взлетать. Это предотвратит "эксплойты" (бесконечное обогащение на одном маршруте) и заставит диверсифицировать грузы.

Используем нелинейную кривую (логарифм или экспоненту) для расчета средней цены при оптовой закупке партии $X$:
$$P_{avg\_buy} = P_{start\_buy} \cdot \left(1 + \gamma \cdot \ln\left(\frac{Q_{start}}{Q_{start} - X}\right)\right)$$
*Суть:* Первые 10% товара со склада стоят дешево. Когда игрок вычищает 90% склада, цена последних единиц возрастает в разы. Это заставляет оставлять товар на рынке для местных NPC.

---

### Уровень 4. Глобальные события и Время (Динамика Галактики)
Чтобы модель "дышала", вводим глобальные события $E(t)$, которые меняют базовую цену или множители на лету.

*   **Война в секторе:** Спрос на медикаменты и оружие ($D_g$) во всей галактике умножается на 1.5.
*   **Эпидемия на аграрной планете:** Предложение еды ($R_{i,g}$) падает до 0.
*   **Открытие нового маршрута:** Логистическое плечо сокращается, цены выравниваются.

**Финальная формула цены:**
$$P_{final} = P_{buy/sell} \cdot E_g(t) \cdot DistanceFactor$$
*(Где $DistanceFactor$ — логистический коэффициент: чем дальше станция от центра галактики/варповых узлов, тем выше базовые цены из-за дефицита).*

---

### 🎮 Как сделать это УВЛЕКАТЕЛЬНЫМ (Геймдизайн поверх математики)

Сама по себе математика — это просто калькулятор. Увлекательным её делают **информационная асимметрия** и **риск**.

#### 1. Скрытые переменные и "Информация"
Игрок **не должен** видеть точные цифры $F$ (заполненности) или $E(t)$ (глобальных событий).
*   Вместо точной цифры игрок видит индикатор в интерфейсе: *"Дефицит"*, *"Норма"*, *"Избыток"*.
*   Чтобы узнать точную цену на соседней станции, игрок должен купить "Информацию у брокера" или "Перехватить переговоры дальнобойщиков".
*   *Геймплейный крючок:* Игрок тратит деньги и время, чтобы узнать, что на станции "Крон-7" сейчас *Дефицит* медикаментов. Он летит туда, но по пути узнает, что там началась эпидемия (глобальное событие $E(t)$), и цена взлетела еще выше.

#### 2. Фьючерсы и Контракты
Позвольте игроку покупать не сам товар, а "Контракт на поставку".
*   Игрок видит, что на станции А избыток руды. Он может заключить фьючерс, выкупив товар по текущей низкой цене с доставкой через 3 игровых дня.
*   Если за эти 3 дня в соседнем секторе начнется война (потребность в металле вырастет), игрок продаст контракт NPC-перекупщикам втридорога, даже не перевозя груз.

#### 3. Контрабанда и "Черный рынок"
Нелегальные товары не имеют $P_{base}$. Их цена зависит **только** от $F$ (заполненности) и уровня коррупции/присутствия полиции на станции.
*   Математика черного рынка более волатильна (коэффициенты $\alpha$ и $\beta$ выше).
*   Риск: если игрок везет нелегал, цена продажи может упасть, если на станцию прилетит патруль (случайное событие, меняющее локальный модификатор).

#### 4. Эффект "Слухов" (Туман войны для экономики)
Игрок может слышать слухи в тавернах/барах: *"Говорят, шахты на Титане встали из-за забастовки"*.
Это значит, что $R_{i, руда}$ скоро упадет до нуля. У игрока есть выбор:
1.  Поверить слуху, загрузить трюмы рудой на текущей станции и лететь через полгалактики.
2.  Случайно оказаться правым и заработать состояние.
3.  Оказаться неправым (слух — фейк, созданный конкурентами для манипуляции рынком) и потерять деньги на топливе.

---

### Пример игрового сценария (Как это работает на практике)

1.  **Игрок на станции "Аграрий-9".** Видит, что Еда в *Избытке* ($F=0.9$). Цена покупки упала на 40% от базовой.
2.  **Действие:** Игрок скупает 80% всей еды. Срабатывает *Проскальзывание* (Уровень 3) — цена на последние 10% товара была в 2 раза выше, чем на первые. Средняя цена закупки выросла.
3.  **Анализ:** Игрок помнит, что в секторе "Орион" (3 прыжка отсюда) идет война. Он предполагает, что $E(t)$ для еды там высокий.
4.  **Риск:** Прыжок через 3 системы требует много топлива. Пока он летит, NPC-торговцы могут подвезти еду на "Аграрий-9" (значение $F$ снова вырастет, и когда игрок вернется, продавать будет некому).
5.  **Решение:** Игрок летит в "Орион". По пути его грабят пираты, он теряет 20% груза.
6.  **Итог:** На станции "Орион" Еда в *Дефиците* ($F=0.1$). Станция готова скупать её по цене в 3 раза выше базовой. Игрок продает остатки, отбивает потери от пиратов, платит за топливо и получает чистую прибыль, которая позволяет купить корабль с лучшей броней.

### Резюме для разработчика
Эта модель хороша тем, что она **детерминирована** (разработчик может просчитать баланс и не допустить инфляции), но для игрока она выглядит как **живой, дышащий мир**, где нужно учитывать логистику, риски, сбор информации и влияние собственных действий на хрупкую экономику галактики.

# Математическая модель экономики для космического торговца

## 1. Базовые сущности

**Товары** `i = 1..N` (еда, металл, медикаменты, электроника, люкс, топливо, контрабанда...), у каждого базовая цена `P0(i)`.

**Системы** `j = 1..M`, у каждой:
- тип экономики: аграрная, добывающая, промышленная, хайтек, бедная, столица;
- богатство `wealth(j)`;
- матрица **производства** и **потребления** `prod(i,j)`, `cons(i,j)` (тонн/день) — берётся из таблицы типов:

| Товар | Аграрная | Добывающая | Промышленная | Хайтек | Столица |
|---|---|---|---|---|---|
| Еда | prod++ | prod− | cons+ | cons+ | cons++ |
| Металл | cons | prod++ | cons+ | cons | cons+ |
| Электроника | cons | cons | prod | prod++ | cons+ |
| Люкс | − | − | cons+ | cons+ | prod/cons++ |

Это создаёт **структурные** различия цен — стабильные торговые маршруты.

## 2. Ядро модели: цена через запасы

Ключевая идея: цена определяется **текущим запасом товара на рынке** относительно целевого.

```
target(i,j) = cons(i,j) * DAYS_BUFFER        # буфер, напр. 10 дней потребления

fair(i,j)   = P0(i) * type_mult(i,j) * wealth_mult(i,j)   # "справедливая" цена

price(i,j)  = fair(i,j) * ( target(i,j) / stock(i,j) )^ALPHA
```

- `ALPHA` = 0.6–1.0 — эластичность. При `ALPHA = 1` падение запаса вдвое удваивает цену.
- Ограничить: `price ∈ [0.4·fair, 3.0·fair]`.
- `stock(i,j)` — видимый игроку уровень запасов (можно показывать как "дефицит/избыток").

**Пример:** еда, `P0 = 100`. На аграрной планете запас 2000 при цели 1000 → цена `100·(0.5)^0.8 ≈ 57`. В工业... в промышленной системе запас 400 → `100·(2.5)^0.8 ≈ 208`. Разница — чистая мотивация лететь.

## 3. Динамика (тик = 1 игровой день)

```
stock(i,j) += prod(i,j) − cons(i,j)        # экономика системы
stock(i,j) += npc_flow(i,j)                # торгуют NPC (см. п.7)
stock(i,j) *= 1 + gauss(0, SIGMA)          # шум, SIGMA ≈ 0.03–0.07
stock(i,j)  = clamp(stock, 0.15·target, 6·target)
```

Шум создаёт **временные** возможности: сегодня тут дёшево, завтра — нет.

## 4. Спред покупка/продажа

```
buy_price  = price * (1 + spread)          # игрок платит больше
sell_price = price * (1 − spread)          # игрок получает меньше
spread ≈ 0.05–0.12, меньше в богатых/крупных системах
```

Спред = «комиссия рынка», он съедает микроприбыль и заставляет искать **серьёзные** перекосы цен.

## 5. Глубина рынка (главный механизм против эксплойтов)

Сделки игрока меняют запас, а значит — цену. Реализуйте **пошаговое исполнение** ордера:

```python
def player_buy(i, j, qty):
    cost = 0
    while qty > 0:
        chunk = min(qty, 0.05 * target(i,j))   # рынок "впитывает" по 5%
        p = buy_price(i, j)
        take = min(chunk, money/p, cargo_free)
        if take < 1: break
        stock[i,j] -= take; cost += take*p; qty -= take
    return cost
```

Эффект: нельзя скупить весь рынок дёшево или слить 1000 тонн по максимальной цене — чем больше сделка, тем хуже средняя цена. Игрок учится **дробить маршруты** и возить оптимальные партии. Это та самая «глубина», из-за которой торговля в Elite/Dwarf Fortress увлекательна.

## 6. События и новости (драйвер игрового процесса)

Событие = `{товар/категория, список систем, множитель, длительность, затухание}`:

```
E(i,j,t) = 1 + A * exp(−t/τ)     # умножается на цену
```

Примеры:
- **Неурожай** — `prod(еда) × 0.2` на 20 дней → еда дорожает;
- **Война** — `cons(медикаменты, оружие) × 3`;
- **Фестиваль** — спрос на люкс ×3;
- **Новый завод** — `prod × 2` → цены падают → шанс закупиться;
- **Блокада пиратов** — `npc_flow = 0`, цены вверх, риск вверх.

**Механика новостей:** о событии сразу узнаёт локальная система, к соседям информация «доходит» с задержкой 2–5 дней (или мгновенно — через покупку ленты новостей). Игрок, который купил еду *до* того, как рынок узнал о неурожае, чувствует себя умным — это и есть увлекательность.

## 7. NPC-торговцы (чтобы экономика жила)

Каждый тик между **соседними** системами (граф маршрутов, не все со всеми): если разница цен > порога, NPC перевозят понемногу товар туда, где дороже:

```
flow ∝ β * max(0, price_k − price_j − cost),  β — маленький
```

Это медленно закрывает **случайные** дисбалансы (шум), но **структурные** (типы экономик) сохраняются — иначе игрок найдёт один «вечный» маршрут и игра сломается.

## 8. Издержки и риск

Чтобы расстояние и риск имели цену:
- **Топливо** — фикс. цена за прыжок/св. год;
- **Время** — цены тикают, пока игрок летит: дальний маршрут = упущенная прибыль, значит должен платить больше;
- **Пиратство** — вероятность `p(маршрут)`, ожидаемый убыток `p·L`. Опасные системы сами по себе дорожают (мало подвоза) — риск оплачивается рынком;
- **Контрабанда** — маржа ×3–5, риск штрафа/конфискации.

## 9. Целевые числа для баланса

| Параметр | Значение | Зачем |
|---|---|---|
| ALPHA | 0.6–1.0 | чувствительность к дефициту |
| SIGMA (шум/день) | 0.03–0.07 | волатильность |
| spread | 0.05–0.12 | отсекает мусорные сделки |
| DAYS_BUFFER | 5–15 | глубина рынка |
| clamp цены | 0.4–3.0 × fair | защита от абсурда |
| Маржа типового маршрута | 15–40% брутто | ощутимый прогресс |
| Партия игрока за раз | 10–30% от target | рынок не ломается |
| Ранняя прибыль | 10–20% капитала за рейс | мотивация |

Прогрессия: больший трюм → упор в глубину рынка → игрок уходит в дальние/рискованные системы, где дисбалансы больше.

## 10. UI, который делает модель увлекательной

- **История цен** (буфер последних 60 тиков) — графики, анализ;
- **Среднегалактическая цена** товара как ориентир «дёшево/дорого»;
- Индикатор запаса («избыток/дефицит» вместо точных чисел — дороже продавать информацию);
- Лента новостей со слухами;
- Автопилот расчёта лучшего маршрута — только как **покупаемая** услуга, не даром.

## Минимальная версия (если полная симуляция избыточна)

Если не хочется хранить запасы — модель на случайных блужданиях вокруг справедливой цены (процесс Орнштейна–Уленбека):

```
x(t+1) = x(t) − θ·x(t) + σ·ξ,        x = ln(price / fair)
price(t) = fair · e^x
```

`θ` отвечает за возврат к среднему, `σ` — за размах колебаний. Остаются спред, события и глубина рынка — уже играбельно, а запасы можно добавить позже: модель построена так, что они подключаются без переделки остального.

# Математическая модель экономики космического торговца

Суть увлекательной торговли — **колеблющиеся цены + понятные причины этих колебаний + ограничения** (время, топливо, грузовместимость). Игрок должен видеть причинно-следственные связи: «в системе X идёт война → растёт спрос на оружие → цена ↑».

---

## 1. Цена товара на станции

Для каждого товара *i* в системе *s* цена формируется так:

```
P(i,s) = P₀(i) × K_industry(i,s) × K_supply(i,s) × K_event(i,s) × K_player(i,s) × N(μ=1, σ=0.05)
```

| Множитель | Значение | Эффект |
|---|---|---|
| `P₀(i)` | Базовая цена товара | Задаёт «шкалу» (вода дешёвая, антиматерия дорогая) |
| `K_industry` | 0.45 – 1.8 | Система-производитель → цена покупки низкая; система-потребитель → высокая |
| `K_supply` | 0.6 – 1.6 | Запасы на станции: перенасыщение дешевле, дефицит дороже |
| `K_event` | 0.5 – 2.5 | Война, эпидемия, засуха, технобум (см. п. 4) |
| `K_player` | ~1.0 ± | «Игрок слишком часто возит один товар» — антифарм фактор (п. 5) |
| `N(...)` | шум | Живая рыночная «дрожь» ±5% |

**Разрыв бид/аск:** у каждой станции спрос/предложение:

```
Цена продажи игроку (station sells): P_ask = P × (1 + m + r)
Цена покупки у игрока (station buys): P_bid = P × (1 − m − r)
```

где `m` — маржа станции (0.08–0.20, больше у «диких» станций), `r` — репутация игрока: при высокой репутации `m` снижается → рост чувствуется.

> ⚡ Ключевое правило баланса: **без событий выгодных связок с низким риском быть не должно** — маржа съедает маржу. Профит дают именно события и информация.

---

## 2. Динамика запасов и цен (живая экономика)

Моделируем запас товара `Q(i,s)` как ванну с протекающим краном:

```
Q(t+Δt) = Q(t) + (Prod_s − Cons_s) × Δt − Q_sold_by_player − Q_bought_by_player
P зависит от Q: P = P₀ × (Q_ref / Q)^γ,   γ ≈ 0.7   (эластичность)
```

- Система-производитель: `Prod > Cons` → запас растёт → цена падает до `K_industry` минимума.
- Покупка игроком большой партии **сдвигает цену против него** (следующая партия уже дороже) — это само по себе увлекательно: «выгодно ли скупать всё сразу или лучше дробить?»
- Рынок самовосстанавливается с характерным временем `τ ≈ 2–5 игровых дней` — стимулирует двигаться дальше, а не сидеть на одной связке.

---

## 3. Карта экономических циклов

Распределите товары по «производственной цепочке», чтобы игрок строил маршруты:

```
Руды (в шахтёрских системах) → металлы (плавильные) → компоненты (промышленные)
   → корабли/роботы (верфи) → продаются в ядре галактики
```

Эффективная доходность маршрута:

```
Доходность = Σ (P_bid(пункт назначения) − P_ask(пункт отправления)) / (время_перелёта × расход_топлива)
```

Балансируйте так, чтобы оптимальная цепочка состояла из **3–5 систем** с суммарной наценкой 60–120% за рейс, а доходность на единицу времени была выше у рискованных/дальних маршрутов.

---

## 4. События — двигатель азарта

Событие в системе *s* задаёт множители спроса:

```
War:        K_event(оружие)=2.5, K_event(едa)=1.4, K_event(медикаменты)=1.3
Epidemic:   K_event(медикаменты)=3.0, K_event(еда)=1.2, пассажиропоток ↓
Drought:    K_event(вода, еда)=2.2
Tech boom:  K_event(электроника)=2.0 (спрос), руда=1.3 (предложение ↑, цена ↓)
Pirate raid: локально K_supply ↓, цены ↑, но риск потерять груз
```

Механика: **событие случается → новости в баре станции → умные игроки летят первыми → цены выравниваются за τ дней → окно закрывается.**

Для разнообразия — прогнозы (иногда ложные): «намёки» портальных новостей, где цены изменятся *через N дней*. Это даёт глубину: не только реагировать, но и предугадывать.

---

## 5. Анти-эксплойты (важно для увлечённости)

1. **Усталость рынка к игроку:** `K_player(i,s) = (1 + β × n_i)` для покупки, `(1 − β × n_i)` для продажи, где `n_i` — сколько игрок перевёз товара *i* за последние дней. Это убивает заезженные «золотые маршруты».
2. **Инвентаризация/упаковка:** у каждого товара объём и делимость — крупнотоннажные дешёвые товары (руда) vs компактные дорогие (чипы): разные стратегии по грузовместимости.
3. **Износ корабля и топливо:** расходы, масштабирующиеся с расстоянием, заставляют считать не «разница цен», а «разница цен на единицу времени».

---

## 6. Прогрессия игрока

- Капитал *W* растёт экспоненциально, но с трением: нужные апгрейды (трюм, двигатель, щиты, торговые лицензии) стоят ~×2.5–4 от текущего капитала — создают «ступеньки» азарта.
- Репутация *R* от торговли/контрактов: снижает маржу `m`, открывает контрабанду, эксклюзивные товары.
- Торговые контракты: генерируемые заказы «доставь X в Y за Z дней» — это планки-сюрпризы поверх свободной торговли.

---

## 7. Формула «интереса» (сводный принцип)

```
Интерес = (несправедливость цен) × (скорость её исчезновения) × (информационное преимущество игрока)
         − (рутина повторения) − (трение времени/топлива)
```

Настраивайте τ событий и K_industry так, чтобы в каждой системе при входе игрок находил **1–2 разумных сделки**, но золотая жила требовала бы риска (дальний прыжок, пираты, конкуренты-NPC).
