# Промт для DeepSeek Harness: Three.js игра «Стойка бариста»

## 1. Роль и режим работы

Ты — senior frontend/Three.js разработчик. Работай в **стандартном режиме** Harness. Не начинай писать код, пока не прочитаешь это задание полностью и не составишь краткий план реализации (5–7 пунктов) в ответном сообщении. После подтверждения плана переходи к созданию файлов.

**Рабочая директория:** пустая папка проекта (создай её содержимое с нуля).
**Стек:** HTML5 + Three.js (ES modules через CDN или локальный `three.module.js`) + vanilla JavaScript. Без сборщиков, без бэкенда. Всё запускается открытием `index.html` через локальный сервер (Live Server / `npx serve`).

## 2. Игровая концепция

Игрок — продавец-бариста в кафе. Перед ним стойка-прилавок с **тремя полками**. На полках лежат **12 ингредиентов**. За стойкой стоит **очередь клиентов**. Каждый клиент произносит монолог-заказ. Игрок должен кликнуть по нужным ингредиентам на полках, чтобы собрать заказ. На всё даётся **3 секунды**.

**Ключевое правило:** стоимость заказа равна сумме стоимостей выбранных ингредиентов. Игра не проверяет «правильность» набора напрямую — она проверяет, совпадает ли итоговая стоимость собранного заказа с эталонной стоимостью, которая вычислена из монолога клиента.

## 3. Состав ингредиентов (12 штук, 3 категории)

Создай массив `INGREDIENTS` в отдельном файле `data.js`. Каждый объект:

**Категория A — Салаты (3 шт.):**

**Категория B — Напитки (3 шт.):**

**Категория C — Основные блюда (3 шт.):**
- `main_pasta` — «Паста карбонара» — цена 150
- `main_burger` — «Бургер» — цена 130
- `main_soup` — «Суп дня» — цена 110

**Дополнительно (3 шт., распредели по полкам):**
- `extra_bread` — «Хлеб» — цена 20
- `extra_sauce` — «Соус» — цена 15
- `extra_dessert` — «Десерт» — цена 50

**Итого:** 12 ингредиентов. Три полки: полка 1 — салаты + хлеб, полка 2 — напитки + соус, полка 3 — основные + десерт. Расположение задай вручную через `shelfIndex` и позицию на полке.

## 4. Меню и генерация заказа

**Меню** — это не список для игрока, а эталонная база для генерации заказов. Клиент в монологе называет **блюда и напитки**, а не ингредиенты напрямую.

Создай `MENU` — массив из 9 «готовых позиций» (3 салата, 3 напитка, 3 основных). Каждая позиция меню ссылается на **один или несколько** ингредиентов. Например:

```js
{ id: 'menu_caesar', displayName: 'Цезарь', ingredientIds: ['salad_caesar', 'extra_bread'], totalPrice: 140 }
{ id: 'menu_latte', displayName: 'Латте', ingredientIds: ['drink_latte'], totalPrice: 80 }
{ id: 'menu_pasta', displayName: 'Паста карбонара', ingredientIds: ['main_pasta', 'extra_sauce'], totalPrice: 165 }
```

**Логика генерации заказа:** при появлении нового клиента случайно выбери **2–3 позиции из меню** (без повторов). Сумма их `totalPrice` — это `targetPrice`. Сформируй **монолог** — текстовую строку, которая естественно перечисляет выбранные позиции. Пример: «Мне, пожалуйста, Цезарь, Латте и Пасту карбонара. И побыстрее, у меня поезд через десять минут.»

Монолог выводится в HTML-оверлее (не в 3D), крупным шрифтом.

## 5. Игровой цикл и правила

### Состояния
- `IDLE` — ожидание, очередь пуста или клиент ещё не подошёл.
- `ORDERING` — клиент произнёс заказ, идёт отсчёт 3 секунды, игрок кликает по ингредиентам.
- `SUCCESS` — заказ собран, сумма совпала, клиент уходит.
- `FAIL_TIMEOUT` — 3 секунды истекли, заказ не собран.
- `FAIL_WRONG` — игрок нажал «Готово», но сумма не совпала.

### Очередь клиентов
- Одновременно в 3D-сцене визуально присутствуют **до 4 клиентов** (простые капсулы/цилиндры с разными цветами, стоят за стойкой).
- Первый клиент в очереди — «активный». Его монолог отображается на экране.
- После `SUCCESS` или `FAIL_TIMEOUT` активный клиент уходит, очередь сдвигается, следующий становится активным.

### Таймер
- При переходе в `ORDERING` запускается таймер на **3000 мс**.
- Таймер отображается в HTML (полоса или число).
- Если таймер истёк: активный клиент удаляется, **счётчик ошибок +1**, **штраф += стоимость этого заказа** (то есть `targetPrice` активного клиента). Переход к следующему клиенту.

### Сборка заказа
- Игрок кликает по 3D-объекту ингредиента на полке (Raycaster).
- Выбранный ингредиент добавляется в «корзину» (визуально — подсвечивается на полке, и появляется строка в HTML-списке справа).
- Повторный клик по уже выбранному ингредиенту **убирает** его из корзины.
- В корзине отображается **текущая сумма** (сумма цен выбранных ингредиентов).
- Кнопка «Готово» (HTML) фиксирует заказ.

### Проверка
- `currentSum === targetPrice` → `SUCCESS`, **счётчик обслуженных +1**, корзина очищается, клиент уходит.
- `currentSum !== targetPrice` → `FAIL_WRONG`, **счётчик ошибок +1**, **штраф += targetPrice**, корзина очищается, клиент уходит (тот же клиент считается «проваленным»).
- Таймаут обрабатывается отдельно (см. выше).

### Счётчики (всегда видны в HTML)
- **Обслужено:** количество `SUCCESS`.
- **Ошибок:** количество `FAIL_TIMEOUT` + `FAIL_WRONG`.
- **Штраф (руб.):** сумма `targetPrice` всех проваленных заказов.

## 6. 3D-сцена (Three.js)

### Камера и ракурс
- PerspectiveCamera, позиция примерно `(0, 4, 8)`, `lookAt(0, 1, 0)`.
- Фиксированный ракурс: игрок видит стойку, три полки за ней и очередь клиентов слева/справа от стойки.

### Освещение
- `AmbientLight` (мягкий, интенсивность 0.6).
- `DirectionalLight` сверху-сбоку (интенсивность 1.0, с тенями или без — на твоё усмотрение, приоритет — производительность).

### Стойка и полки
- Стойка — `BoxGeometry` (широкая, невысокая), цвет тёмно-коричневый.
- Три полки — три `BoxGeometry`, закреплённые над стойкой на разной высоте (`y = 1.5, 2.2, 2.9`).
- Задняя стенка — простая плоскость или куб, чтобы полки не висели в пустоте.

### Ингредиенты
- Каждый ингредиент — простой 3D-объект (куб/цилиндр/сфера) с уникальным цветом из `INGREDIENTS`.
- Объекты кликабельны через `Raycaster`.
- При наведении курсора — `cursor: pointer` (изменение CSS-курсора на canvas).
- При выборе — подсветка (изменение `emissive` или `scale`).
- **Важно:** каждый ингредиент должен иметь `userData.ingredientId`, чтобы связать 3D-объект с данными.

### Клиенты
- Простые капсулы/цилиндры разных цветов, стоят в линию за стойкой.
- Позиции: `x = -2, -0.7, 0.7, 2`, `z = -1`, `y = 0.5` (примерно).
- При уходе клиента — просто `scene.remove()` и сдвиг остальных (можно без анимации, но плавный `lerp` приветствуется).

### HTML-оверлей (поверх canvas)
- **Левая панель:** монолог клиента (крупный текст), таймер (полоса или число).
- **Правая панель:** список выбранных ингредиентов с ценами, итоговая сумма, кнопка «Готово».
- **Верхняя панель:** счётчики «Обслужено / Ошибок / Штраф».

## 8. Технические ограничения и требования к качеству

1. **Никаких внешних библиотек** кроме Three.js. Не использовать React/Vue/GSAP/Ammo.js.
2. **Raycaster** должен корректно работать при изменении размера окна (`window.addEventListener('resize', ...)`).
3. **Таймер** реализуй через `performance.now()` в игровом цикле, а не через `setInterval` — чтобы не было рассинхронизации при потере фокуса вкладки.
4. **Клик по ингредиенту** должен обрабатываться только в состоянии `ORDERING`. В остальных состояниях клики игнорируются.
5. **Кнопка «Готово»** должна быть неактивна (`disabled`), если корзина пуста.
6. **Никаких `alert()`.** Все сообщения — через оверлей.
7. Код должен быть читаемым, с комментариями на русском в ключевых местах (генерация заказа, проверка суммы, таймер).
